Context

Where Tasks sits

  • One line on Flatiron for interviewers who don't know it — e.g. "Flatiron builds software for community oncology clinics, including the OncoEMR electronic health record."

Keep this to 45 seconds. The goal is just enough context that the problem slide lands. Don't explain the whole EHR.

The problem

The user pain, stated as a sentence — not "improve tasks"

  • Evidence #1 — a number if you have one (volume, time lost, backlog, NPS verbatim)

This is the slide interviews dig into. Be ready for: "How did you know this was the right problem?" and "What did you deprioritize to work on this?"

What got hard
